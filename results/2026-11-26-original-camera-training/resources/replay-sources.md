# Human replay sources

The Gensokyo Replay Archive lists 10,981 downloadable replay entries across TH10, TH12 and TH13 in the November 26 inventory. TH10 contributes 4,065 entries, TH12 contributes 3,933 and TH13 contributes 2,983. The archive retains the player spelling, shot, replay type, upload date and source link. The accompanying compressed JSON Lines file contains one record per listing. [TH10 archive](https://maribelhearn.com/gensokyo?game=MoF) · [TH12 archive](https://maribelhearn.com/gensokyo?game=UFO) · [TH13 archive](https://maribelhearn.com/gensokyo?game=TD)

Each listing counts one source record. A single player may submit many replays, one binary may appear in multiple archives, and a practice replay may cover one stage. Training sample counts come from separate capture receipts. Each admitted example pairs a contemporaneous stock-game camera image with the four future input ticks decoded from that exact replay. The receipts record the source checksum, captured tick span, eligible control frames and native input agreement. Group complete source players before producing training and held examples.

The TH13 archive starts on August 13, 2011. The verified TH13 camera captures use retail version 1.00c. Replay compatibility with an earlier trial build requires independent playback and an input-alignment check. The metadata index includes public archive entries and source links. See [machine-readable counts](external-replay-source-counts.json) and [compressed index](external-replay-candidates.jsonl.gz).

TH12 also has an external C++ implementation with a retail replay comparison tool. Its documented validation coverage and proposed use for accelerated training are described in the [TH12 rollout resource](th12-headless-candidate.md).

## Qualifying an earlier-title replay

Start the selected stage in a private copy of the user's authenticated retail game. Set the stock renderer to a 640×480 window. The collector reads the original replay tick and the gameplay input consumed by the game around each screenshot. It crops the 384×448 playfield to 96×112 grayscale pixels. The sample stores the previous eight and next four replay input words. Movement, Focus and Shoot use the first future tick. Bomb is set if any of the four future words contains a Bomb press.

TH10 uses bit 0x4 for Focus. TH12 and TH13 use bit 0x8. TH10 coordinates have 100 fixed-point units per native pixel, and TH12 has 128. Independently compare those integers with the original floating-point player coordinates. Scan the gameplay words against the source bytes to locate the replay clock offset, then check input timing against player displacement and register the moving sprite across consecutive images. The TH10 and TH12 eligibility checks cover player presence and coordinate agreement. Dialogue and respawn have not been independently identified on these builds. [Original TH10 data structures](https://github.com/N0zoM1z0/th10/blob/main/src/ReplayManager.hpp) · [TH12 input and replay timing](https://github.com/vittorioromeo/th12_hfr/blob/main/docs/games/TH12_DEVNOTES.md) · [TH12 coordinate reference](https://github.com/Tweet-META/th12/blob/main/scripts/reverse/sample-player-bomb-position.py)

Use both the public uploader name and the player name saved in the original replay header to check split membership across the earlier corpus. Keep any collision out of the admitted roster. The stock game's private stage selection can show the recorded player name, shot and difficulty before acquisition. A complete source file and a visible window alone cannot establish the identity of the rendered camera stream.
