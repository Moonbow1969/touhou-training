# Decoupling TH08 native-prefix archival from the clock reply

The existing reader reads the whole original key prefix on each qualifying snapshot, writes a temporary file, closes it, and replaces the stage file before the 21-field pipe reply. A slow filesystem can delay the clock timestamp published by the parent. This offline reference moves archive file access, prefix comparison, checksums and replacements to a worker or an explicit finalization step.

## Proposed production boundary

1. Keep the native source qualification in the reader. On a due request, obtain an owned byte snapshot while the original origin/cursor and stage still identify that recording. Preserve the stable bracket or revalidate a late read, and surface an invalid capture. Passing a game-memory pointer across threads would allow the original to advance or discard the buffer. The prototype accepts an already captured byte string. Native memory-read cost still requires measurement.
2. Hand the owned prefix to one bounded mailbox per stage. A newer accepted prefix for the same stage subsumes an older queued prefix. The writer takes a snapshot reference and releases the mutex before any filesystem operation. Other stages retain their pending snapshots. Preserve raw mode 0, native cursor = origin + 36 + 2 × tick, zero-based stage 0–2, stable read, positive origin, count < 65,535, periodic flags 4 / +32 threshold, and flags 0 / strictly larger tick+1. A flags-0 snapshot is an evidence candidate. During post-credit menu input a stage may resume briefly. An explicitly confirmed endpoint or transition needs its own native count and evidence hash.
3. The worker normally appends only the new words plus a 12-byte header/checksum per journal record. If an older word changes, the newer image replaces the logical prefix. Above a per-stage journal limit of 266,232 bytes the worker compacts via same-directory replacement. There are at most three pending full prefixes, three previously persisted in-memory prefixes and one writer operation. Each native prefix is at most 131,068 bytes. The caller's scratch space and Python allocation overhead are additional. Serialization and finalization also use bounded transient buffers. Steady-state disk payload is linear for a growing immutable source, apart from headers and infrequent compaction.
4. Register the final proven count for each visited stage, release gameplay inputs, close the producer, drain the worker, re-read complete journals, create each byte-identical little-endian count + words file, and publish sealed.json last. Require the stage set, counts and SHA-256 to match the independent endpoint and each file before grading. Surface worker failure. A forced process kill may leave a partial journal and lose the latest in-memory snapshot. Recovery returns the checksum-complete prefix with an incomplete-tail indication. A journal or isolated stage file alone cannot certify a credit.
5. The present native bracket closes the request pipe without waiting for a durable archive receipt. The container can stop before the reader finishes. Production integration would need an explicit finalization request, a completion/error acknowledgement, a bounded timeout and a shutdown path that waits for the reader. Original timing, input parity, terminal word and stage transitions still require qualification on the new build. The parent also flushes its separate clock log per query.

## Offline results

The fixture reapplied the old eligibility gate to chronological clock rows from two earlier engineering credits. The source at each due tick was a slice of the already archived final native recording. This verifies eligibility, count convention and final bytes. Historical memory changes between reads are unavailable. A synthetic fixture separately changed previously published words.

| Engineering clock | Eligible snapshots | Legacy full-prefix bytes | Candidate journal + final stage file | Exact final |
|---|---:|---:|---:|---:|
| pipeline-engineering | 115 | 420,168 | 7,784 + 7,260 | 3,628 words |
| second-pipeline-engineering | 73 | 168,600 | 4,868 + 4,584 | 2,290 words |

The two final stage files matched the prior implementation byte for byte. These sizes are application payload and omit directories, filesystem block allocation, flush metadata and the final receipt. Coalescing depends on machine scheduling. A separate fixture held the disk worker behind an event until twelve additional submissions across three stages had returned. Reusing the source scratch buffer preserved all three byte sequences. Additional checks cover corrected historical words, CRC rejection, incomplete header/payload recovery, disk-full errors, compaction, insufficient terminal counts and the cursor-offset eligibility rule. Native game throughput and latency remain unmeasured for this candidate.

Source files are under tools/rollout-worker-probe/th08-trial002/tick4. Run check_archive_async.py with --fixture for each prior engineering credit directory and --report to save the results. Machine-readable verification is in [offline-checks.json](offline-checks.json).
