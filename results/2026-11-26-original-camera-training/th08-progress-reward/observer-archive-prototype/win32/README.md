# TH08 asynchronous native recording candidate

The original fixed observer remains available as reader.c. This engineering candidate lives in reader_async.c and archive_writer.h. The build-only shell entry point is build_archive_candidate.sh OUTPUT_DIRECTORY. The 32-bit candidate PE has SHA-256 e44967b0c464633077f04aca4959b12cba87987a9d72e99a24b12db8d5c3a58a.

## Control contract

Start in a fresh, isolated capture directory. Each request byte q produces the existing 21-field original-state reply. On the existing 32-tick or terminal-flag eligibility gate, the original input prefix is copied into owned memory. Post-copy checks verify the object, stage, flags, original stage pointer, cursor and tick before the request is marked stable. The file writer uses one event-driven Win32 thread and releases its short memory-copy lock before performing I/O. The worker stores the maximum complete prefix in a separate bounded partial file per stage. If original historic bytes change it rewrites the corrected image. Normal monotone snapshots append new words and update the count. Snapshot coalescing never mixes stages. The reader owns eight fixed 131,068-byte word buffers in total (including scratch), approximately 1.00 MiB excluding operating-system thread stacks and file caches.

For a true engineering credit, confirm the original Continue or ending screen and stage evidence independently. Derive each stage's maximum eligible count from stable original telemetry, and require the endpoint's final original word. A flags-0 terminal tail contributes tick+1 only when the original cursor equation holds. Menu activity can reactivate a stage. Freeze the counts and request the seal before ranking navigation. An ordinary periodic snapshot cannot by itself establish Game Over.

Send the ASCII command s followed by a space and three unsigned decimal word counts separated by spaces, terminated by LF. Use 0 for an unvisited stage. The worker drains, and the reader compares the independently supplied count for every stage, flushes, re-reads and compares every word to its owned final image. It moves each verified partial to native-record-stage-N.bin without replacing a prior file, and publishes native-archive-sealed.tsv last. Its control reply is SEALED followed by the same three counts. The final manifest also records worker writes, coalesced snapshots and application bytes written. The existing q data reply retains its prior schema.

Wait for the explicit reply, successful process exit and the manifest before opening ranking or stopping the container. The reader waits up to 20 seconds for the writer to drain. The supervisor must also bound the entire seal operation because filesystem flushes or readbacks can take additional time. A naked pipe EOF attempts a drain and exits unsealed. Disk failure, missing stage counts, a stale output directory, an unexpected command or a missing final receipt fails the credit. Any leftover partial after a hard stop is diagnostic only. Host-side SHA-256 for each final file and original endpoint evidence remains the caller's job.

## Verification

Both compiled binaries used i686-w64-mingw32-gcc-posix, C11, optimization level 2, all warnings as errors, and a deterministic PE timestamp. The same native writer ran under Windows against two earlier engineering recordings and reproduced all 3,628 and 2,290 words byte for byte. Synthetic second and third stages checked stage separation and a corrected earlier word. A manual event held the writer before any disk operation until the submitting thread had sent every pending prefix. The unsuccessful cases were unannounced EOF, an incorrect terminal count and an unwritable output. Five cases passed. [Build, fixtures and digests](compiled-fixture-results.json)

The peer collector owns the two original engineering runs. Copying the native prefix and checking its post-read bracket remain on the request side. Their cost, scheduler delay, the parent bracket's clock-log flushes and the last physical key still need evaluation under the mounted Wine filesystem.
