# 261124 TH14 纯策略训练协议

**正式目标是原作 TH14 Steam 1.00b Normal 灵梦 A 的 1CC。** 第一个关口是从原作第一关开场进入第二关。策略直接输出移动、低速、射击和 Bomb，每次动作推进四个原作帧。混合控制器可以验证环境和提供基准成绩。训练及评估的纯策略动作关闭几何避弹、瞄准修正与自动 Bomb。

## 任务、奖励和结束条件

第一关目标用真实进 Stage 2 判定成功。整局目标用过完六关、原作进入结局且续关计数为零判定 1CC。Practice 关段用预先核对的目标阶段完成事件，原作 Practice Clear 和单独的 Boss 阶段结束各有标签。首版策略可使用原作给的全部生命和 Bomb。掉一条命后继续采样，只有实际 Game Over 才结束失败的信用。

| 事件 | 基础奖励 | Gymnasium 语义 |
| --- | ---: | --- |
| 达成当前目标 | +1 | `terminated=True` |
| 原作 Game Over | 0 | `terminated=True` |
| 存活、掉一条命后继续、单次使用资源 | 0 | 继续当前 episode |
| 采集时长上限 | 0 | `truncated=True`，用最终观测做 value bootstrap |
| 失焦、菜单异常、复位不符、错误难度或续关 | 无 | 拒绝该段并单独记录故障 |

首版用 `gamma=1.0` 来表达有限原作信用里的清关概率，GAE λ 固定为 0.95。采用下面的同起点双臂实验。

- **A · 稀疏清关。** 只用上表的基础奖励。
- **B · 稀疏清关＋阶段势函数。** 用 `Φ(s)=0.25 × 已完成的原作里程碑数 / 该任务的已验证里程碑数`。在每次动作后加 `Φ(s')−Φ(s)`。真终止时令下一状态的势函数为零，采集截断保留活跃状态的势函数。成功和失败轨迹的整局回报目标保持一致。势函数给出中间学习信号，不能替代见到成功轨迹。 [Potential-based reward shaping](https://people.eecs.berkeley.edu/~pabbeel/cs287-fa09/readings/NgHaradaRussell-shaping-ICML1999.pdf) · [Time limits and bootstrapping](https://proceedings.mlr.press/v80/pardo18a.html)

里程碑在训练之前从原作轨迹核对。以相位身份和实际推进为准，分别记录击破、超时推进、掉命、符卡取得。HP 只在同一 Boss 指针、同一阶段、相同最大 HP 和符卡 ID 且可受伤的相邻观测间统计。Boss 换相位、脚本扣血、通关结算和分数变化都不能伪装成伤害反馈。首版奖励不含 HP、分数、已存活时间或按键次数。Bomb 消耗来自原作库存事件，记录无法可靠归因的同帧拾取或补给。

## 课程和原作验证

1. **先验收环境。** Stage 1 开场和 thprac 中 Boss 前 Chapter 3 分别确认初始章节、难度、机体、生命、Bomb、火力、实际时间零点和复位结果。每个调入训练的入口验收 20 次复位，每次 32 次固定动作。双时钟推进四帧的比例至少 99%，左右各自合格命令的位移响应至少 98%。另外取实际进 Stage 2、最后一条命用完、采集截断三种原作轨迹，核对每局的结束标签和回报。整局任务复位要验证可退出 Game Over 并重开信用，续关键不能充当 Retry。 [现有练习复位探针](../scripts/probe_th14_practice_resets.py)
2. **从已有成功示范、接近目标的入口补状态覆盖。** 用示范和环境基准确认 Stage 1 后半段入口能采到真实成功事件，再锁定入口配置。如果 Chapter 3 仍很少见到后段 Boss，先验收更接近关尾的 Boss 入口，再逐步扩到 Chapter 3。短关段的成功不填入原作开场清关率。入口使用与真实轨迹相符的资源档位，明确记录 thprac 的章节和时钟语义。 [Reverse curriculum generation](https://proceedings.mlr.press/v78/florensa17a.html)
3. **把训练搬回原作开场。** 两臂用同一组固定入口比例，首轮开场和合格后段入口各 50%，按已验收任务重新初始化回报和相位记忆。每臂从既有的 title-balanced SFT seed 61 checkpoint 和全新 critic 开始，用训练种子 211 与 397，在每个种子做 8,192 次有效决策。沿用约 78 万参数的四头模型与现有观测，阶段与结算检测在环境一侧。两臂共用动作间隔、优化器配置、观测与入口分配表。唯一实验变量是势函数。
4. **冻结后用原作开场验收。** 每个训练种子跑 8 组旋转顺序的成对 episode，共每臂 16 局。同组跑一次冻结的 SFT 父策略，建立全生命开场基准。固定评估种子 1201–1208 和 1301–1308，原作 RNG 仍未受控。主要指标是进 Stage 2 的比例和抵达时的剩余生命。另报无掉命清关、Bomb 实际消耗、首掉命、Boss 阶段覆盖、贴边活动时间和基础设施故障。贴边按实际位置的连续帧计量，并按阶段分层。

## 什么时候继续投算力

- **环境验收前只做诊断。** 奖励审计已用归档里的 8 次真实进 Stage 2、一次 1CC 和一次续关结局核对。正式版第一关 Game Over 的人工复位已确认。菜单最后一项重开信用，在原作第一关第 7 帧读到 0 续关、2 条备用命和 3 个 Bomb。刚开新信用就发 Retry 时，第一次对齐读到第 82 帧，超出请求的第 30 帧。首次 Retry 等到第 180 帧后，20 次活动关卡复位均对齐到第 30 帧，双时钟四帧 **640/640**，左右位移响应各 **160/160**。首次掉命、Practice Clear、采集截断和势函数取消另做合成检查。Chapter 3 和自动 Game Over 复位仍需验收。 [可运行审计](../scripts/audit_th14_clear_objective.py) · [审计结果](../results/2026-11-24-th14-clear-objective-audit.json) · [开场复位实测](../results/2026-11-24-th14-stock-opening-reset-gate.json)
- **两个臂都没采到真实成功。** 先改入口覆盖和资源初始分布。试验没有检验到“势函数是否提高通关”的充分条件。
- **进入下一预算。** B 相比 A 每个训练种子都不退步，两种子合计至少 5/16 清关、比 A 多至少四局，再加一个训练种子和第二个交互预算。这是项目晋级门槛。保留全部逐局数据和配对差异。
- **进入全局任务。** 原作从头开始每个训练种子至少 6/8 进第二关，成功局剩余生命中位数至少 1，再用自然承接的资源联合训练后段。逐步把评估推进到完整信用，最终报告真正的 1CC 和各关失败位置。

先把环境、成功样本覆盖和清关奖励验实。KL、动作熵、模型尺寸和跨作品扩展各自是后续消融。用已观测的退化行为选择变量。试玩版目前可验证四帧并行吞吐，缺少 Boss 相位和真实 Bomb 库存字段，生存曲线单独归档。

正式版先沿用本地 learner。旧的正式版训练约 14 决策/秒，采样和重置占约 97% 时间。给每组分别记采样、复位、同步和优化耗时，learner 成为实测瓶颈后再改变训练设备。训练日志保留 input、代码和 checkpoint 的哈希，活跃权重继续保留最近两份。 [吞吐与原作预算记录](devlog/261123-native-ppo-scale.md)
