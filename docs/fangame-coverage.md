## Proposed train and test assignments

For the first family-level test, train on admitted original-game training titles plus Kikamu and Abyss Soul Lotus. Seal all three Fantastic Danmaku Festival games together as the test family. Preserve the existing original-game title holdouts. Freeze title, build, task, observation modality, difficulty, character configuration and seeds before selecting checkpoints. Permit mechanical adapter checks on a fixed, published action trace. Exclude held-out frames, replays, game-derived normalization statistics, encoder fitting, RL updates and policy tuning from every training stage, including world-model training.

A second experiment can train on Fantastic Danmaku Festival I and II and test on III. Report it as transfer within the series. Seal Kikamu and Abyss Soul Lotus in that experiment to measure transfer to separate fangame projects. Give each experiment its own data manifest and trainable checkpoints.

## Adapter and replay intake

1. Qualify one acquired Steam build per game on Windows, then repeat input, restart and observation tests in an isolated Wine or Proton worker if available. Record app ID, executable hash, runtime, profile and action mapping. Test Easy or Normal Stage 1, then add game-supported Hard, Lunatic and Extra tasks as distinct rows. Record practice starts and story starts independently.
2. Use cropped playfield pixels and input logging where structured observations are unavailable. Measure actual observation cadence and action response. Require a verified native tick source before comparing exact four-tick stepping or pooling with the TH14 structured learner. Keep one action head for each supported control or mechanic. Mask unavailable actions and record character switching, shields or Hyper according to the title’s actual semantics.
3. Create a short replay with logged keyboard states and known directional, focus and mechanic transitions. Play it twice on the originating build and compare stage transitions, actions where observable, and clear or score events. Only add expert actions when a per-title decoder or an aligned live input capture verifies the playback. If a title offers only video for a given run, record it as observation-only. Start replay sourcing with locally recorded demonstrations and contributor-provided native files. Track source, build, replay hash, contributor group, rank and shot. Group all stages and builds of the same run together.
4. Publish per-title first miss, furthest stage, clear rate, resources used and decision throughput. Count technical start or reset failures separately. Report pixel-policy and structured-policy benchmarks with their observation modality so differences remain interpretable.
