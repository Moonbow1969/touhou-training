# Perfect Cherry Blossom retail 1.00b replay camera

This observer reads the original Japanese retail game on a private Wine/Xvfb display. The frozen census and author allocation are under `results/2026-11-26-original-camera-training/th07-retail-original-humans`. The executable and data file must come from a user-owned installation. The release provides the observer and measurements.

## Acquisition

Each new replay lane copies only `th07.exe`, `th07.dat` and the assigned public replay into a fresh private game directory. The original installation, save and configuration are outside the writeable lane. The base Docker image is the project’s original Wine/llvmpipe environment. Two lanes use a maximum of two CPUs each. Each author has separate original replay-menu entries for Stage 1 and Stage 2.

On Momentum the experiment root was `/var/tmp/moonbow-th07-retail-100b-preflight`. Put the frozen protocol there, original privately supplied game files under `input`, and the six public replay inputs named `public-NN.rpy` under `sources`. Put the files in this directory and the repository's `replays/inspect_rpy.py` under `tools`. Compile the native observer for the guest glibc with `cc -O2 -o tools/sensor-v2 tools/retail_sensor.c -ldl`. The exact engineering binary on Momentum had SHA256 `9f19c6e2102143c24c3676b03d315d887cc1c8de1981a7add95563ce2829ead5`. Record the toolchain when rebuilding. Stage replay playback is selected from the stock menu at normal speed.

First run `python3 tools/run_case.py public-01.rpy 1 preflight/green-v2-s1` and the corresponding Stage 2 command. Run `python3 tools/seal.py preflight/green-v2-s1 1` and its Stage 2 equivalent. Only then can `python3 tools/fleet.py` acquire the other authors. Every capture keeps the original menu selections, opening, endpoint, sampled grayscale stream, original raw full-color witness frames, native clock/keys/XY and all replay input words. The frozen optimizer cap is 2,000 eligible windows per stage and author.

The sampler brackets the X capture using the original replay-manager clock, input cursor, current and previous input and stage ID. Coordinates agree with the midpoint of two original player rectangles on eligible rows. After playback tick `t`, current and previous masks read original records `t-1` and `t-2`. The label predicts record `t`. For the Bomb head it marks an actual rising edge in `t..t+3`. Cropping the sparse original BGRA witnesses at (32,16) to 384×448, then applying 4× box grayscale reduction, reproduces the archived 96×112 frames byte for byte. A pair requires a real four-tick difference. Missing cameras, jump gaps and mismatched player bounds do not enter the training bank.

## Connecting a future original Game Start policy

The human capture already qualifies the clean build, camera, original stage, immediate and previous input, and native player position for evaluation. Original record mode still requires a separate engineering credit and evidence for the following changes before using a model score.

1. Follow ordinary Game Start → Normal → Reimu → Homing Amulet with no loaded replay. Record opening HUD resources, original stage and the new replay header’s shot and difficulty. A fresh profile's separate Practice menu highlights Stage 1 only.
2. In the four-tick actor, replace every trial-specific `0x11c9ae8` / `0x11c9d24` / `0x11c9d2c` read with the retail clock/stage `0x62f858` / `0x62f85c` and two-byte keys `0x4b9e50` / `0x4b9e58`. Retain independent repeated reads over image capture and pause/resume, the original per-process watchdog and four-head physical X input. Verify rising edges of left/right/up/down, focus, fire and Bomb against the stock recorder. Actor images contain no native coordinates.
3. Keep genuine native stage IDs throughout. A retail stage block begins with 44 bytes of state followed by 4-byte records. Record mode initializes the first input to zero, advances the cursor and writes; playback consumes the current cursor and then advances. Check the current word against the actual saved RPY for several offsets, especially on transitions away from neutral. Validate the cursor and native samples at every retained action, tolerate only the final physical partial window, and prove zero stale middle actions. Use a newly generated Normal Reimu A file to establish the retail **record** phase.
4. Verify native spare life and Bomb values against original HUD and against independently saved replay-stage snapshots. Retain original Game Over or ending, terminal inventory, first and later stage entries, deaths, spends and no-Continue choice. Requalify the stock result-screen image/template against this retail build. An official practice/replay Stage 2 launch does not count as policy Stage 2 entry.
